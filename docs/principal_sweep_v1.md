# Principal student sweep v1

This protocol fixes the principal comparison before implementing or training
the remaining student families. It asks how much state-dependent nonlinear
recurrence is needed to reproduce the frozen teacher's closed-loop defence
under tracking loss. The changed variable is the history mechanism. The task,
public observation, action adapter, teacher targets, training seeds, data
budgets and evaluation episodes are controlled.

The successful GRU-64 engineering pilot motivates including the conventional
recurrent baseline and shows that the current training/export path can produce
a strong closed-loop controller. It is not principal evidence: half of its
training aggregate was generated by the structured `k=2` policy. That GRU
checkpoint and the existing structured `k=2` checkpoint are excluded from all
principal statistics.

## Families and seeds

The sweep contains feed-forward, ten-step finite-stack, structured
`k=0,1,2,4`, and GRU-64 students. Each family is trained with seeds
14303--14307. Seed identity is paired across families. All recurrent families
use a 64-value state, the same 64--32 `SiLU` observation encoder, the same
64--2 action head and the previous requested action. The stack retains ten
puck-position/visibility triples but receives no velocity. Parameter count,
core parameter count, recurrent memory bytes and complete policy-carry bytes
are reported rather than treated as matched quantities.

## Equal family-specific shadow data

Every seed first trains a collector checkpoint from scratch on the same frozen
20,000-episode deterministic-mean teacher dataset. Each family's five
collectors then contribute 4,000 trajectories apiece on identical shot and
blackout schedules. This gives exactly 20,000 complete shadow-labelled
episodes per family. The five partitions are pooled within their family and
never across families. All five final models in that family are retrained from
scratch on the same 20,000 teacher-controlled plus 20,000 family-shadow
episodes.

A complete episode is the budget unit because the policies are trained on
complete recurrent histories. Policy-dependent terminal times can cause the
number of valid teacher queries to differ. Those counts are reported; they are
not equalised through adaptive top-ups or truncation. Weak families receive
no extra round, trajectories or teacher queries. The loss gives each complete
episode equal total weight, so a family does not gain greater optimisation
weight merely because its collectors produced longer episodes.

## Validation and untouched test

Validation uses the existing 225-shot `direct_launch_v3` validation split at
blackout lengths 0, 5, 10, 15 and 20. The original v3 test split is not
untouched because Stage B used it. A new, fixed 225-shot `principal_test`
split with seed 5303 is therefore defined in
`configs/env/direct_launch_v3_principal_test_v1.yaml`.

The new test remains closed until all 35 student checkpoints, family datasets,
shadow-budget audits, validation episode files, efficiency measurements,
analysis code and this analysis plan are frozen and hashed. It is then opened
once for the five core blackout lengths and the predeclared 25-step
extrapolation. No retraining, reselection or hyperparameter change is allowed
after release.

The primary outcome is test save rate at a 20-step blackout. The full curve,
25-step extrapolation, teacher-relative gap, outcome categories and every raw
training-seed point are mandatory. Contact timeouts and bare timeouts are not
saves; faults are failures. Planned differences use a paired hierarchical
cluster bootstrap over matched training seeds and shot units, with alias pairs
kept together. The sweep reports estimates and intervals without significance
language or choosing a winning family.

## Efficiency measurements

Every frozen checkpoint is measured through its exported NumPy float32
batch-one runtime on Marvin's Intel Core Ultra 9 285. The benchmark uses one
process, one thread, logical CPU 0, 10,000 warm-up calls and ten repetitions of
10,000 timed calls. It includes history/recurrent update, encoder and action
head, while excluding simulation, rendering, inverse kinematics, checkpoint
loading and process start-up. Median and 95th-percentile latency are reported
per checkpoint alongside the five seed-level values for each family.

The canonical machine-readable protocol is
`configs/experiments/principal_sweep_v1.yaml`. Corrections require a new
version before the principal test is opened.
